# V4L2：给内核视频设备的合同

V4L2（Video4Linux2）是 ioctl API。设备文件 `/dev/videoN`。同一套接口服务：摄像头 capture、内存到内存（M2M）编解码、scaler。

核心头文件：`<linux/videodev2.h>`。本仓库全部经 `v4l2sl_xioctl()` 发出，方便测试挂钩。

## 队列模型

每个 M2M 设备至少两条队列：

| 队列 | 方向 | 无状态解码里装什么 |
|---|---|---|
| **OUTPUT** | 用户 → 设备 | 压缩码流（H.264 slice、AV1 裸 tile） |
| **CAPTURE** | 设备 → 用户 | 解完的 NV12/NV15/… |

生命周期：

```
S_FMT          告诉内核宽高、fourcc、plane 大小
REQBUFS        要 N 个 buffer（本仓库 OUTPUT 4，CAPTURE 24 或 AV1 40）
QUERYBUF+mmap  或 用 dmabuf
STREAMON
循环:
    QBUF   把一块交给内核
    DQBUF  内核用完还回来
STREAMOFF
REQBUFS(0) 释放
```

对照：`v4l2sl_setup_output_queue`、`v4l2sl_setup_capture_queue_count`、`v4l2sl_queue_output`、`v4l2sl_dequeue_buffer`（`device.c`）。

**index 是用户态和内核共用的整数。** 桥用 `free_out_bufs[]` / `free_cap_bufs[]` 当空闲栈。双 push 会让两帧写进同一块 CMA——AV1 copy-out 修的就是这个。学 V4L2 自己写用户态时，**buffer 所有权**要比 memcpy 更小心。

## 格式协商

`VIDIOC_S_FMT` / `G_FMT` / `TRY_FMT`。用户填的宽高只是愿望，驱动可以改 stride、对齐高度（1080→1088）、fourcc。

桥在 `v4l2sl_ensure_capture` 里读回真正的 `cap_stride` / `cap_height` / `cap_pixelformat`。HEVC Main10 经常：先按 NV12 建队，SPS 来了发现 10-bit，再 STREAMOFF + 重 S_FMT 成 NV15。这叫 **renegotiate**，日志里有 `renegotiate capture`。

fourcc 是四字符：`NV12`、`NV15`、`H264`、`AV1F`（内核宏是 `V4L2_PIX_FMT_*`）。**用 fourcc 认设备，不要用 video 号。**

## 两种 M2M

**有状态：** OUTPUT 丢 Annex-B，设备自己解析、自己管 DPB。JPEG、RGA、很多摄像头 ISP 属于这类。稳态 ioctl 很少。本仓库 `jpeg.c` / `vpp.c` + `v4l2sl_m2m_state` 缓存 S_FMT。

**无状态：** 每帧必须附带 *已经填好的* 控制结构（SPS/PPS/frame header 的 V4L2 版）。设备不解析起始码。必须配合下一页的 **Request API**。

## 控制（controls）

`VIDIOC_S_EXT_CTRLS` 提交 `v4l2_ext_controls`。无状态解码的「这一帧怎么解」全是 control：

- H.264：`V4L2_CID_STATELESS_H264_SPS` 等
- AV1：`V4L2_CID_STATELESS_AV1_SEQUENCE` / `_FRAME` / `_FILM_GRAIN` / `_TILE_GROUP_ENTRY`

**which** 字段决定作用域：

- 普通 / 当前请求：跟这一帧走
- `V4L2_CTRL_WHICH_CUR_VAL` 全局：挂在设备上

AV1 的 **sequence 必须全局**。request-scoped 的 sequence ioctl 在 hantro 上会 *成功*，然后 OUTPUT QBUF `EINVAL`。这是学 controls 时最坑的一点：errno 不在 S_CTRL，在下一发 QBUF。

多条 control 可以一次提交（`count > 1`）。桥把 AV1 grain+frame+tile 合成一次，ioctl 次数 186→66。语义不变，少几次用户态/内核往返。

## poll 与完成

QBUF 之后用 `poll(POLLIN)` 等 CAPTURE 完成，再 DQBUF。超时桥给 3 秒，到了就 `decode_reset`（两边 STREAMOFF），因为内核可能还握着 buffer，不能只把 index 推回用户态空闲栈。

`V4L2_BUF_FLAG_ERROR`：这一帧硬件没解好。桥把它映射成 VA 的 skipped surface，而不是失败整个 entrypoint。

## 自己练

```bash
v4l2-ctl --list-devices
v4l2-ctl -d /dev/video1 --list-formats-out   # OUTPUT fourcc
v4l2-ctl -d /dev/video1 --list-formats       # CAPTURE fourcc
media-ctl -d /dev/media3 -p                  # AV1 的图
```

把输出和 `probe.c` 的扫描逻辑对照。
