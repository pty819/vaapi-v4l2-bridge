# AV1 Hot-Path Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut the AV1 per-frame path from 9 to 7 ioctls by merging the three request-control submissions into one `S_EXT_CTRLS`, and remove the audited waste (silent tile truncation, duplicate parse attempt, per-frame `getenv`).

**Architecture:** All changes live in the userspace driver (`~/vaapi-v4l2-bridge` on `liyifan@192.168.1.21`, built in `builddir/`, installed to `/usr/lib/aarch64-linux-gnu/dri/`). Kernel objects submitted are byte-identical to today — only their submission sequencing, diagnostics, and userspace bookkeeping change. Spec: `docs/superpowers/specs/2026-09-04-av1-hotpath-design.md`.

**Tech Stack:** C (libva driver), V4L2 request API, meson/ninja, bash test matrix.

## Global Constraints

- Repo: `liyifan@192.168.1.21:~/vaapi-v4l2-bridge` (SSH key auth; sudo via `echo liyifan | sudo -S`).
- Every code change is applied by writing a patch script to a local file and `scp`-ing it — never heredoc-embed C string literals through ssh (`\n` gets eaten and splits literals).
- Build gate: `cd builddir && ninja` must succeed with no NEW warnings before any install.
- Install: `sudo cp -f builddir/v4l2stateless_drv_video.so /usr/lib/aarch64-linux-gnu/dri/` — the matrix and manual decodes load the SYSTEM copy.
- Decode environment for all manual checks: `export LIBVA_DRIVER_NAME=v4l2stateless`.
- Decode correctness is judged ONLY by hw-vs-sw framemd5 compare, never by exit code or absence of errors.
- No fallback path for combined control submission (user decision): if the kernel rejects it, the matrix fails loudly and the change is revisited.
- Commit style: `av1: lowercase imperative summary` — one commit per task, push once at the end.

**Files:**

- [ ] **Step 2: Restructure the submission region**

In `v4l2sl_av1_translate`, keep the grain struct fill block and the frame/fill calls exactly as they are, then replace the three separate submissions with this ordering — ALL controls are built and submitted BEFORE the output buffer is popped:

```c
    /* Film grain — kernel expects the control even when unused. */
    struct v4l2_ctrl_av1_film_grain grain;
    /* ... existing grain fill block, unchanged ... */
    struct v4l2_ext_control req_ctrls[3];
    unsigned n_req_ctrls = 0;

    req_ctrls[n_req_ctrls].id = V4L2_CID_STATELESS_AV1_FILM_GRAIN;
    req_ctrls[n_req_ctrls].ptr = &grain;
    req_ctrls[n_req_ctrls].size = sizeof(grain);
    n_req_ctrls++;

    req_ctrls[n_req_ctrls].id = V4L2_CID_STATELESS_AV1_FRAME;
    req_ctrls[n_req_ctrls].p_av1_frame = &frame;
    req_ctrls[n_req_ctrls].size = sizeof(frame);
    n_req_ctrls++;

    /* Tile-group entries depend only on tile_params[] — not on the
     * copied output buffer, so they move ahead of the pool pop. */
    struct v4l2_ctrl_av1_tile_group_entry entries[32];
    if (n_tiles > 0) {
        uint32_t base = 0;
        for (int i = 0; i < n_tiles; i++) {
            memset(&entries[i], 0, sizeof(entries[i]));
            entries[i].tile_offset = base;
            entries[i].tile_size = tile_params[i]->slice_data_size;
            entries[i].tile_row = tile_params[i]->tile_row;
            entries[i].tile_col = tile_params[i]->tile_column;
            base += tile_params[i]->slice_data_size;
        }
        req_ctrls[n_req_ctrls].id = V4L2_CID_STATELESS_AV1_TILE_GROUP_ENTRY;
        req_ctrls[n_req_ctrls].ptr = entries;
        req_ctrls[n_req_ctrls].size = sizeof(entries[0]) * n_tiles;
        n_req_ctrls++;
    }

    struct v4l2_ext_controls req_ctrls_batch = { 0 };
    req_ctrls_batch.controls = req_ctrls;
    req_ctrls_batch.count = n_req_ctrls;
    /* One S_EXT_CTRLS per frame. All ids are written every frame, so an
     * early return after this point can never leave a stale mixture on
     * the request. Failure is terminal — no per-control fallback. */
    if (v4l2sl_set_request_controls(request_fd, v4l2_fd, &req_ctrls_batch) < 0) {
        fprintf(stderr, "v4l2stateless: failed to set AV1 request controls\n");
        return VA_STATUS_ERROR_OPERATION_FAILED;
    }
```

Then the existing output-buffer pop / bounds-check / memcpy loop keeps its place (delete the old per-control submissions and the old tile-entry block that followed the memcpy; the memcpy loop's bounds error keeps its `v4l2sl_out_pool_push` unwind since it runs after the pop). Control order FILM_GRAIN → FRAME → TILE_GROUP mirrors the old sequence; request-scoped control storage is id-indexed, not order-sensitive.

The old error paths collapse: grain failure warned-and-continued (now fatal with the batch — acceptable, it always succeeded on target hw), frame failure returned without unwind (unchanged semantics), tile-group failure pushed `out_buf_idx` (that unwind now lives only in the memcpy bounds check).
